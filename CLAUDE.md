# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Converter — an offline desktop app (PySide6) that converts files between formats and is **honest about quality**: every conversion yields a `QualityVerdict` (lossless / lossy / unsupported) shown as a badge with a reason. Never advertise or silently perform a conversion that loses data or can't actually run without saying so — this principle drives the verdict/availability logic.

## Architecture

- `core/` — framework, no GUI and no I/O backends. Key pieces:
  - `pipeline.run_job()` is the **single execution path** for every conversion (GUI and CLI both go through it). It resolves the converter, checks availability, then converts — and never raises (failures come back as `ConversionResult(ok=False)`).
  - Converters self-register via the `@register` decorator (`core/registry.py`); the GUI only talks to the registry, never to converter classes by name. Adding a format = add/extend a converter, no UI changes.
  - `Converter.verdict()`, `format_available()`, and `pair_available()` (src→dst direction) drive what the UI offers vs. greys out.
- `converters/` — one module per category (image/audio/video/data/document/**model3d**), each `@register`-ed.
  - `mesh3d.py` (trimesh, MIT, pure-Python) converts 3D meshes in-process like `image.py` (no external tool, works in PORTABLE). Inputs obj/stl/ply/glb/gltf/3mf; outputs obj/stl/ply/glb/gltf (**3mf is input-only**). 3mf import is gated on the optional `lxml` (`format_available("3mf")` greys out without it; lxml normally rides in via python-docx). A multi-object scene going to a single-mesh target (stl/obj/ply) is flattened and the verdict is **downgraded to lossy at runtime** (mirrors `image.py`'s multi-frame override). Detection: glb/ply via magic bytes, 3mf via ZIP inspection, gltf via JSON structure (distinguished from `data` json by requiring `asset` + meshes/scenes/nodes), ASCII STL via `solid`+`facet normal` sniff — **binary STL has no magic and falls back to the extension tiebreaker (0.3)**, the one place content-detection can't fully apply. glTF is exported with **embedded buffers** (one self-contained file) and OBJ side files are named after the output (`chair.mtl`, `chair_material_0.png`, spaces → `_`, never overwriting): trimesh's default fixed names (`gltf_buffer_0.bin`, `material.mtl`) made batch outputs in one folder overwrite each other.
  - `textdoc.py` (`TextDocConverter`, priority 20) is the **structured document engine**: one intermediate representation (`docmodel/`: `read_pdf`, `read_docx`) and writers (`write_docx`, `write_markdown`, `write_text`, `write_html`). It claims `pdf → {docx, odt, rtf, md, txt, html}` and `docx → {md, txt}`; everything else stays on LibreOffice or the markup engine. `pdf → docx` has a `docx_layout` option: `structure` (real Word headings/lists/tables, default) or `visual` (one `w:framePr` frame per printed line, page breaks between pages). `odt`/`rtf` are docx + a **second LibreOffice hop**, so they need FULL mode and soffice. The engine is in-process and MIT (pdfminer.six + python-docx); **do not** reintroduce pdf2docx/PyMuPDF (AGPL, won't ship). The IR is the seam for any future AI refinement: `Document in → Document out`, deterministic by default. PDF reading order is a recursive xy-cut (vertical columns first, then the widest horizontal gap) applied to paragraphs, tables and images too; borderless tables are detected conservatively (numeric 2-column tables with ≥3 rows, or 3+ columns with a caption, ≥50 % numeric cells, or a bold short dense header), so prose/infographics stay paragraphs. A table that shares its row bands with the prose of another page column is kept whole: rows are grouped across the prose band (`_continues_table`), and the prose column is dropped only when it is left of the table, looks like prose (median ≥4 words per cell), the remaining columns still pass the table guards, and the page has text beside them (`_split_at_gutters`, `_has_text_beside`). Rotated text (`LTChar.upright` false: arXiv margin stamps, watermarks) is collected apart and dropped, unless the whole page is rotated, so its glyphs neither merge into body lines nor become headings. A numbered non-bold line slightly larger than the body (`1 Introduction`) is a heading and does not merge into the following paragraph. Images extracted from PDFs are re-encoded to lossless PNG when they arrive in an uncompressed format (pdfminer exports most of them as raw BMP), so the IR and the Markdown/HTML writers stay small; already-compressed formats are kept as they are. DOCX reading walks the paragraph in document order, so `w:hyperlink` text survives as `Run.link` (md/html/docx), inline `w:drawing` images become `ImageBlock`s, and `w:headerReference`/`w:footerReference` land in `Document.headers`/`footers`; `w:gridSpan`/`w:vMerge` become `col_span`/`row_span`, and `Table.text_grid()` is the compact logical grid (one column per cell that starts there) shared by md/txt and the corpus digest.
  - `registry.resolve(src,dst)`, among converters that claim the pair ordered by **descending `priority`**, returns the first whose `_pair_fully_available` holds (`available().ok` + `format_available(src)` + `format_available(dst)` + `pair_available`); if none qualify it returns the highest-priority claimant (so `run_job`'s error message stays sensible). This mirrors `targets_for`, which prefers the available converter — otherwise the UI could offer a pair via an available low-priority converter while `resolve` routed it to an unavailable high-priority one. Do **not** let anything but `DocumentConverter`/LibreOffice claim docx/odt→html: it is the only path that preserves cell colors/shading via inline CSS.
- `data.py`: CSV/TSV are read as text with the **sniffed delimiter** (`;` CSVs, kept on csv→csv) and encoding (UTF-8, then cp1252/latin-1), header assigned by hand so duplicate columns survive (renamed only toward json/yaml/xml records, with a runtime lossy verdict). Same-format xlsx/ods/xml/**yaml** are byte copies; yaml→json is **lossy** (comments, YAML 1.1 booleans, dates → ISO strings).
  - `markup.py` (`MarkupConverter`, priority 12, in-process, PORTABLE too) is the **markup engine** that replaced pandoc (GPL-2, ~200 MB in the bundle). `markupdoc/`: readers build one sanitized HTML tree (`tree.Node`, `MarkupDocument`) — md via **markdown-it-py** (MIT; CommonMark + GFM tables/strikethrough, the reference renderer), html via a tolerant stdlib parser, epub via OPF spine + archive images, odt via defusedxml on content.xml (styles resolved with inheritance: bold/italic/underline/strike/sup/sub/monospace; Preformatted Text/Quotations/Title/Horizontal Line paragraph styles; footnotes moved to the end and declared), txt as paragraphs with `preserve_spaces`. Writers: md (GFM, escaping, column alignment, fenced code with longer fences), txt, html (one file: local/archive images as data-URIs), docx (python-docx native styles, `_restarted_num_id` reused so every list restarts, merges, hyperlinks), odt (odfpy, named styles LibreOffice recognises; `add_text` writes spaces as `text:s` because ODF drops a leading literal space), rtf (hand-written ASCII, `\outlinelevel` headings, merges, `\u` escapes incl. surrogate pairs), epub 3 (+ toc.ncx; `mimetype` first and stored, chapters at each h1). Pairs: md/html/epub/txt → md/html/epub/txt/rtf/docx/odt, odt → md/txt only (odt → office stays on LibreOffice for layout), txt→md stays on `plaintext.py`. **Sanitizing**: only whitelisted tags/attributes survive; script/style/iframe… dropped with content; `href` only http(s)/mailto/tel/relative; `_HTML_VOID` (meta, link…) must be recognised or a `<meta>` in `<head>` swallowed the whole body. **Images are never downloaded**: local files are embedded only if Pillow (or the SVG sniff) says they are images, remote ones stay links in md/html and are dropped+declared elsewhere. Verdicts: md→html and txt→anything-but-txt lossless; raw HTML in Markdown, dropped/missing images, merged cells in md, block content in cells, odt footnotes turn the result lossy at runtime (`WriteReport.all_notes`). Archive readers refuse >512 MB uncompressed (zip bomb) and DRM-encrypted EPUBs with a clear message.
  - `plaintext.py` (priority 15) owns txt→md in-process: Markdown symbols escaped, line breaks kept as hard breaks, indentation as `&nbsp;` — pandoc used to re-flow the text under a LOSSLESS badge.
  - `audio.py`: wav/flac targets keep the **source sample format** probed with ffprobe (`probe_audio`; 24-bit stays 24-bit, float WAV stays float). FLAC from float audio, an explicit lower `bit_depth`, or resample/channels/loudnorm options make the verdict lossy (decided at runtime once the source depth is known).
- **Detection** (`core/detection.py`): content beats the extension for binary formats and for JSON/XML that parse, but the weak text sniffs (yaml/csv/tsv) yield to a different **text** extension (`.md`, `.txt`, …) — a README with lists used to become YAML. BMP needs a valid DIB header, not just `BM`. `docmodel.types.is_bullet`: `-`/`–`/`*` need a following space (so `-5 °C` stays text) and `—` is never a bullet.
- PDF reading: a PDF is "scanned" only if it has <10 chars **and** its first pages contain images (a one-word text PDF is text); an empty result is an error, never an empty file. Paragraph indent/alignment and list levels are measured inside the paragraph's **column** (`_column_gutters`: a gutter needs ≥3 lines on each side), not from the page margin.
- **PDF reader tolerance** (measured on the 37-PDF Unstructured test set): `_tolerant_classes()` gives a `PDFDocument` that treats a malformed `/Info` dictionary as empty (it is optional; pdfminer rejected the whole file) and a `PDFPageInterpreter` that drops a broken `/ColorSpace` resource (ICCBased without `/N`) instead of failing the page. Every reader entry point (`read_pdf`, `iter_pdf_pages`, the OCR gate's `_probe_first_pages`) uses them. A page that still fails is skipped and counted in `Document.skipped_pages`; glyphs pdfminer can only name `(cid:N)` become U+FFFD and are counted in `Document.undecoded_chars` — both turn the verdict lossy with the count. CCITT (fax) images are decoded by Pillow/libtiff via a synthetic TIFF header (`_ccitt_image`): pdfminer's pure-Python decoder took ~6 s per scanned page, and its BMP export inverts CCITT colours, so it is not a reference.
- **Aligned (borderless) tables** keep **multi-line cells** (`_is_cell_continuation`: a one-cell band under a non-first column, within ~2 lines) and **merged row labels** (`_is_row_label`: a one-cell band left of the row's first column, squeezed between two rows); both are attached to the row above by `_attach_continuations`, and their cells count for column clustering. A row continues the table only if its cells **align** with the row above (`_aligned_with`, measured on the row with fewer cells) and the vertical gap stays within `_close_enough` (≈1.8× the group's row pitch) — so margin-heading prose below a table is not swallowed. When a page has column gutters, prose of a column LEFT of the table (all cells ≥4 words) is ignored for these checks (`_prose_regions` via the `_PAGE_GUTTERS` ContextVar — thread-safe, the GUI converts in parallel); a long description column on the right is never treated as prose. Two-column text-only tables (e.g. the Korean sample) still stay paragraphs by design.
- **Writers** (`docmodel/writers.py`): Markdown escapes everything CommonMark/GFM would interpret (inline `\ ` * _ [ ] < > | ~ &`, line-start `# + - = >` and `1.`), keeps spaces outside `**`/`*`, and escapes `|` in table cells. Lists render through `_list_entries` (per-level counters, start number from the original marker, child indent = parent content column); `ListItem.ordered` lets one list mix numbered items and bullet sub-items. Images go through `_web_image`: only whitelisted types with a real MIME reach a data-URI, others are re-encoded to PNG or dropped and counted in `WriteReport.dropped_images`, which `TextDocConverter` turns into a lossy runtime verdict. The docx writer gives each numbered list its own `w:num` (restarts at 1).
- **DOCX reader** walks the whole paragraph (`_iter_runs`): text inside `w:ins`, `w:fldSimple`, `w:sdt`, `w:smartTag`, `w:customXml` is kept; `w:del`/`w:moveFrom` are skipped. Body/row/cell content controls are flattened, nested tables become tab-separated paragraphs of the cell, and text boxes (`w:txbxContent`, the `mc:Choice` copy only) follow their anchor paragraph.
- **Images**: `_prepare_mode` converts per target (CMYK→RGB, 16-bit scaled to 8-bit, alpha flattened for JPEG, dropped for BMP) and declares each loss; animated sources keep every frame toward gif/webp/tiff; ICO scales the image to the requested square.
- **Video** maps the main video, **all** audio tracks and subtitles (mkv copies all; mp4/mov → mov_text, webm → webvtt for text subs; picture subs or AVI subs are dropped and declared); H.265 in mp4/mov gets `-tag:v hvc1`; the codec always falls back to one the container accepts. Audio keeps cover art for mp3/flac/m4a unless metadata is stripped, and loudnorm keeps the source sample rate.
- **GUI**: size estimates run in a 1-thread `QThreadPool` (never ffprobe on the UI thread; `probe_duration` and the PDF scan check are cached per file+mtime); a typed output folder is used; default targets follow `_PREFERRED_TARGETS` (jpg↔png, mp4, mp3, xlsx, docx…), not the alphabet.
- **Cancel**: `run_job` returns `ConversionResult(cancelled=True)` without starting when the token is already set (queued jobs), ffmpeg is killed as before, and `TextDocConverter` checks between phases. The GUI shows `Cancelled` (re-convertible, not recorded in history).
- `gui/` — PySide6 UI; contains **zero** conversion logic.
- External tools are detected at runtime, never assumed on PATH: `deps.find_ffmpeg/find_ffprobe/find_soffice` also search standard install dirs and a bundled `bin/`.
- **Engine mode** (`core/engine.py`): session-persisted **FULL vs PORTABLE**, toggled live from the toolbar. Drives which converter pairs are offered — FULL requires LibreOffice for faithful Office conversions; PORTABLE falls back to the pure-Python paths (pdf/rtf/pandas/Pillow/ffmpeg). Same "honest availability" principle as the verdict system: a pair unavailable in the current mode shows greyed out with a reason, never silently downgrades.

## Testing

- Run: `python -m pytest -q` (config in `pyproject.toml`, `testpaths=["tests"]`).
- GUI tests set `QT_QPA_PLATFORM=offscreen` — keep that when adding GUI tests, or they need a display.
- Audio/video tests `skipif` ffmpeg/ffprobe absent; document tests `skipif` LibreOffice absent; OCR scanning is gated with a mocked chain (no OCR install needed); `test_mesh3d.py` `importorskip`s trimesh. A passing run may be skipping these — check the skip count. (Full run with the 37-PDF Unstructured corpus in `tests/corpus/local/` and its 36 baselines: **398 passed, 1 xfailed** (`password.pdf`, correctly refused) on Linux with ffmpeg/LibreOffice, measured 2026-10-26; with the markup engine's tests: **426 passed, 1 xfailed**, 2026-10-27. Measure engine changes by digesting every corpus file before/after and diffing: on that set the table work changed exactly 3 documents, all reviewed against page renders. With the corpus, xfails are corrupt/encrypted corpus files.)
- **Real-document corpus:** `tests/test_corpus.py` compares the reconstructed structure (reading order, headings/levels, lists, table grids, images, page breaks) against JSON baselines. Put real PDF/DOCX in `tests/corpus/local/` (gitignored; or set `CONVERTER_CORPUS_DIR`) and create baselines with `CORPUS_UPDATE=1 python -m pytest -q tests/test_corpus.py`, then review/correct the JSON. In update mode an unreadable file without a baseline is skipped; if a baseline exists, reading must still succeed or the test fails. See `tests/corpus/README.md`. This is the measurement harness for future engine changes — run it before/after touching `docmodel/`.
- To verify GUI visuals truthfully (icons, focus rings, real fonts), render on the **native** Qt platform, not offscreen (offscreen lacks window activation and font glyphs).

## Linting

- ruff (`pyproject.toml`, `[tool.ruff]`): line-length 120, target py310, `select = ["F","I","W","B","UP"]` — deliberately does **not** enable whitespace/line-length rules, to avoid fighting the codebase's hand-aligned formatting style.
- A `PostToolUse` hook (`.claude/settings.local.json`) already runs `ruff check --fix --unfixable F401` automatically after every Write/Edit on a `.py` file — no need to manually re-run ruff after editing.

## Subprocess gotcha (important)

Spawn **every external tool** (soffice, ffmpeg, ffprobe, ocrmypdf) with `deps.clean_subprocess_env()`. A PyInstaller-frozen exe injects bundle dirs into `PATH`; without cleaning, LibreOffice's own Python loads our `python313.dll` and export filters fail ("no export filter for docx"). `_libreoffice.py` and `_ffmpeg.py` already do this — don't bypass it. `_ocr.py` runs OCRmyPDF through `_libreoffice.run_with_timeout` (same env cleaning + hard timeout); OCRmyPDF locates Ghostscript via the Windows registry, so the cleaned PATH does not break it. The structured PDF reader itself is in-process (pdfminer) and has no child process.

`run_ffmpeg` also has a watchdog thread (kills ffmpeg on cancel-while-blocked or after 120 s with no `-progress` output) and `probe_duration` passes `timeout=15`; ffmpeg, pdfminer and the markup engine remove their partial output on failure/cancel.

## Packaging (PyInstaller)

- Build: `pyinstaller converter.spec --noconfirm --clean` (onedir; see `/package` skill for the full build+verify flow).
- **CI** (`.github/workflows/ci.yml`): ruff + the full suite on Linux (ffmpeg and LibreOffice installed, so nothing is skipped for missing tools; `-rs` lists skips) and on Windows without external tools, on every PR and push to main.
- **Release build** (`.github/workflows/build.yml`), three jobs. **windows**: checks tag = `__version__` = `version_info.txt`, downloads ffmpeg (gyan.dev **full-shared**, SHA256-verified: same codecs as winget's "full", but ffmpeg.exe/ffprobe.exe share one set of DLLs instead of embedding them twice) installs Inno Setup and, **best-effort** (15 min timeout, `continue-on-error`: its 360 MB MSI once took 35 min from a slow mirror; the install is bounded *inside* the step — `choco --execution-timeout`, `timeout 12m apt-get` — because a step timeout leaves the process alive, and on Linux an orphan apt-get held the dpkg lock so the `.deb` round trip failed; that step also runs `dpkg --configure -a` and waits for the lock), LibreOffice — only so the selftest covers FULL mode, never bundled; builds, prints the 15 largest files, runs `--selftest`, zips, compiles the installer, **installs it silently, re-runs the selftest on the installed copy and uninstalls it**. **linux** (ubuntu-22.04, so the AppImage needs glibc ≥ 2.35): static ffmpeg/ffprobe (BtbN GPL) for the AppImage; two PyInstaller builds (with tools → AppImage, `CONVERTER_BUNDLE_TOOLS=0` → .deb); selftest on the bundle, on the AppImage (Ubuntu **and** a `fedora:latest` container with only desktop libs), and a .deb round trip (apt install → `converter --selftest` → remove, nothing left). **release** (needs both): one `SHA256SUMS.txt` for all four files and the notes; on a `v*` tag it creates the **draft** release (a person publishes it). PRs touching packaging run everything except the draft; `workflow_dispatch` too.
- **Linux packages** (`installer/linux/`): `build-deb.sh` → `converter_X.Y.Z_amd64.deb` (installs to `/opt/converter`, launcher script `/usr/bin/converter` — a script, not a symlink, so PyInstaller finds `_internal`; `Depends: ffmpeg` + Qt's xcb/EGL libs, `Recommends: libreoffice-writer`; menu/icon caches refresh via dpkg triggers, no maintainer scripts). `build-appimage.sh` → `Converter-vX.Y.Z-x86_64.AppImage` (AppDir with `AppRun` → `usr/lib/converter/Converter`, built with appimagetool `--appimage-extract-and-run` because CI has no FUSE). `converter.desktop` is shared; `gui/app.run` calls `setDesktopFileName("converter")` so Wayland desktops match window and icon. Config lives in `~/.config/Converter`.
- **Bundled tools bypass PyInstaller's analysis**: the spec appends ffmpeg/ffprobe (and the shared ffmpeg DLLs on Windows) to `a.datas` **after** `Analysis` as plain `DATA`. Declared as binaries — or even as datas *before* Analysis, which PyInstaller 6 reclassifies — their library dependencies get copied into `_internal`'s root, where the exe in `bin/` never looks: on Linux that was ~230 MB of duplicated system libav*/x265/codec2 libraries (695 → 461 MB; dropping pandoc then 461 → 271 MB). `CONVERTER_BUNDLE_TOOLS=0` builds without them (the .deb). `markdown_it`, `mdurl` and `odf` are collected with `collect_submodules`.
- **Qt trimmed** (`UNUSED_QT_MARKERS` in the spec, mirrored by `converter_app._UNUSED_QT_MARKERS`, kept identical by a test): the app imports only QtCore/QtGui/QtWidgets, but the `qpdf` imageformat and virtual-keyboard input plugins dragged in QtPdf/QtQuick/QtQml/VirtualKeyboard; `.qm` translations are unused (no QTranslator) and `opengl32sw.dll` is Qt Quick's software OpenGL. Filtered from `a.binaries`/`a.datas` (PySide6 121 → 93 MB on Linux). The frozen selftest checks `bundle free of unused Qt parts` and **`main window builds`** (the real MainWindow with the trimmed Qt).
- **Release notes** live in `docs/releases/v<version>.md` (required for a tag): an optional first line `# Title` becomes the release title; the "Verify the download" section is generated by the workflow (any section with that title in the file is replaced). Release flow: bump the version in `converter/__init__.py`, `pyproject.toml`, `version_info.txt` (+ README/PROJECT_OVERVIEW mentions), write the notes, merge, then push the tag `vX.Y.Z` on main.
- **Installer** (`installer/converter.iss`, Inno Setup 6): `iscc /DAppVersion=x.y.z installer\converter.iss` → `dist\Converter-vX.Y.Z-setup.exe`. Per-user by default (no UAC; the first dialog offers all users), Start-menu shortcut, optional desktop icon, uninstaller. `[InstallDelete]` wipes `{app}\_internal` before copying, so an update never keeps modules removed from the bundle. **Never change `AppId`** — it is what makes a new setup update the existing install instead of adding a second one. `%APPDATA%\Converter` (config/history) survives uninstall on purpose.
- **License texts**: the spec copies `licenses/` (GPL-3/LGPL-2.1 for ffmpeg, LGPL-3 for Qt), `LICENSE` and `THIRD_PARTY_NOTICES.md` into `dist/Converter/` next to the exe, and **aborts the build** if a GPL tool is bundled without its license file.
- **Unused optional modules** (`UNUSED_OPTIONAL_MODULES` in the spec: pygame, sqlalchemy, botocore, pydantic, jinja2, rich, pygments, psycopg2, requests, setuptools…) are excluded: PyInstaller collected them from optional imports of pandas/trimesh/fsspec in a crowded build Python. Proven unused by running the full suite and `--selftest` with them blocked at import; the frozen `--selftest` re-checks they are absent (`bundle free of unused optional modules`), and a test keeps the spec list and `converter_app._UNUSED_OPTIONAL_MODULES` identical. Saved 68 MB on a Linux build (763 → 695 MB). The remaining weight is ffmpeg in `bin/` and Qt.
- **Kill any running `Converter.exe` before rebuilding** — a live process locks files under `_internal`, and `--clean` fails with `PermissionError: [WinError 32]` trying to remove `dist/Converter`.
- Entry point is **`converter_app.py`** (absolute import). Do **not** point PyInstaller at `converter/__main__.py` — its relative imports have no package context when frozen, which silently drops Qt from the bundle. `python -m converter` still works via `__main__.py`.
- ffmpeg/ffprobe bundle into `_internal/bin`; assets into `_internal/assets`. Config/presets/history always live in `%APPDATA%\Converter`, never the bundle.
- **Verification tripwires** (see `/package` skill): `_internal/torch` must **NOT** exist (was accidentally bundled once at 4GB); total bundle size was ≈1.07 GB with the old pdf2docx tree (`bin/` ffmpeg+ffprobe+the old pandoc alone 655 MB) — multi-GB still indicates a bundling error. (`trimesh` adds only ~300 KB; the MIT pdf stack is small.)
- `trimesh` lazy-imports its exchange loaders (stl/gltf/ply/obj/threemf), so the spec collects them explicitly: `hiddenimports += collect_submodules("trimesh")` and `datas += collect_data_files("trimesh")` (its `resources/` schema+templates). Without these the exe imports trimesh but fails every 3D conversion. `python-docx` needs `datas += collect_data_files("docx")` (its `default.docx` / default-*.xml templates are opened at runtime). `lxml` (for 3mf) is **not** added explicitly — it arrives via python-docx (pikepdf is excluded).
- The shipped exe has a built-in **`--selftest <path>` CLI flag** — runs one conversion per category via `run_job` with Python stripped from PATH, writes PASS/FAIL + per-category results to a file. Use it as a real smoke test of the frozen build, not just a launch check. `_selftest_honesty_checks` also covers model3d (stl→glb, two stl→gltf in one folder with no side files), `;` CSV→xlsx, txt→md escaping, md/csv detection, wav 24-bit→flac staying 24-bit, Cancel skipping a queued job, and — frozen only — the license texts next to the exe. `_selftest_markup` runs md → html/docx/odt/rtf/epub and epub/odt back, checking the content (heading styles, `text:h`, stored `mimetype`…). In FULL, **`document odt->docx (LibreOffice export filter)`** keeps exercising LibreOffice's DOCX export inside the frozen exe (the historical 'no export filter' bug); txt→docx no longer can, since it is in-process now. `--convert <src> <dst> <out> <report>` remains the tool for one-off frozen checks (e.g. 3mf→stl, which exercises the bundled threemf loader + lxml).
- The structured document engine is **in-process** (no child process, no extra CLI flag). `--selftest` exercises it in PORTABLE (`portable pdf->txt/md/docx/html`) and checks `pdf struct writer-targets` (docx/md/txt/html available) in FULL.

## Conventions

- Code comments are written in **Italian** (match the surrounding style when editing).
- Git repository (`main`); public repo and releases live at
  https://github.com/brighinatommaso-eng/Converter.
- **App icon**: `gui/app._app_icon()` builds the window/taskbar icon from `assets/icons/converter_{16…256}.png`, not from the `.ico` — the `.ico` holds PNG-compressed entries that Qt reads only via the `qico` plugin, and in the Windows build the icon came out empty (generic taskbar icon) while the `.exe` file icon, embedded by PyInstaller, looked fine. `--selftest` checks `window/taskbar icon loads`.
- `gui/theme.py` QSS font-family names must match the loaded font family **exactly** — a mismatch silently falls back to Segoe UI instead of erroring.
