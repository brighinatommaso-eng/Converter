# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Converter — an offline desktop app (PySide6) that converts files between formats and is **honest about quality**: every conversion yields a `QualityVerdict` (lossless / lossy / unsupported) shown as a badge with a reason. Never advertise or silently perform a conversion that loses data or can't actually run without saying so — this principle drives the verdict/availability logic.

## Architecture

- `core/` — framework, no GUI and no I/O backends. Key pieces:
  - `pipeline.run_job()` is the **single execution path** for every conversion (GUI and CLI both go through it). It resolves the converter, checks availability, then converts — and never raises (failures come back as `ConversionResult(ok=False)`).
  - Converters self-register via the `@register` decorator (`core/registry.py`); the GUI only talks to the registry, never to converter classes by name. Adding a format = add/extend a converter, no UI changes.
  - `Converter.verdict()`, `format_available()`, and `pair_available()` (src→dst direction) drive what the UI offers vs. greys out.
- `converters/` — one module per category (image/audio/video/data/document/**model3d**), each `@register`-ed.
  - `mesh3d.py` (trimesh, MIT, pure-Python) converts 3D meshes in-process like `image.py` (no external tool, works in PORTABLE). Inputs obj/stl/ply/glb/gltf/3mf; outputs obj/stl/ply/glb/gltf (**3mf is input-only**). 3mf import is gated on the optional `lxml` (`format_available("3mf")` greys out without it; lxml normally rides in via python-docx). A multi-object scene going to a single-mesh target (stl/obj/ply) is flattened and the verdict is **downgraded to lossy at runtime** (mirrors `image.py`'s multi-frame override). Detection: glb/ply via magic bytes, 3mf via ZIP inspection, gltf via JSON structure (distinguished from `data` json by requiring `asset` + meshes/scenes/nodes), ASCII STL via `solid`+`facet normal` sniff — **binary STL has no magic and falls back to the extension tiebreaker (0.3)**, the one place content-detection can't fully apply. glTF is exported with **embedded buffers** (one self-contained file) and OBJ side files are named after the output (`chair.mtl`, `chair_material_0.png`, spaces → `_`, never overwriting): trimesh's default fixed names (`gltf_buffer_0.bin`, `material.mtl`) made batch outputs in one folder overwrite each other.
  - `textdoc.py` (`TextDocConverter`, priority 20) is the **structured document engine**: one intermediate representation (`docmodel/`: `read_pdf`, `read_docx`) and writers (`write_docx`, `write_markdown`, `write_text`, `write_html`). It claims `pdf → {docx, odt, rtf, md, txt, html}` and `docx → {md, txt}`; everything else stays on LibreOffice/pandoc. `pdf → docx` has a `docx_layout` option: `structure` (real Word headings/lists/tables, default) or `visual` (one `w:framePr` frame per printed line, page breaks between pages). `odt`/`rtf` are docx + a **second LibreOffice hop**, so they need FULL mode and soffice. The engine is in-process and MIT (pdfminer.six + python-docx); **do not** reintroduce pdf2docx/PyMuPDF (AGPL, won't ship). The IR is the seam for any future AI refinement: `Document in → Document out`, deterministic by default. PDF reading order is a recursive xy-cut (vertical columns first, then the widest horizontal gap) applied to paragraphs, tables and images too; borderless tables are detected conservatively (numeric 2-column tables with ≥3 rows, or 3+ columns with a caption, ≥50 % numeric cells, or a bold short dense header), so prose/infographics stay paragraphs. A table that shares its row bands with the prose of another page column is kept whole: rows are grouped across the prose band (`_continues_table`), and the prose column is dropped only when it is left of the table, looks like prose (median ≥4 words per cell), the remaining columns still pass the table guards, and the page has text beside them (`_split_at_gutters`, `_has_text_beside`). Rotated text (`LTChar.upright` false: arXiv margin stamps, watermarks) is collected apart and dropped, unless the whole page is rotated, so its glyphs neither merge into body lines nor become headings. A numbered non-bold line slightly larger than the body (`1 Introduction`) is a heading and does not merge into the following paragraph. Images extracted from PDFs are re-encoded to lossless PNG when they arrive in an uncompressed format (pdfminer exports most of them as raw BMP), so the IR and the Markdown/HTML writers stay small; already-compressed formats are kept as they are. DOCX reading walks the paragraph in document order, so `w:hyperlink` text survives as `Run.link` (md/html/docx), inline `w:drawing` images become `ImageBlock`s, and `w:headerReference`/`w:footerReference` land in `Document.headers`/`footers`; `w:gridSpan`/`w:vMerge` become `col_span`/`row_span`, and `Table.text_grid()` is the compact logical grid (one column per cell that starts there) shared by md/txt and the corpus digest.
  - `registry.resolve(src,dst)`, among converters that claim the pair ordered by **descending `priority`**, returns the first whose `_pair_fully_available` holds (`available().ok` + `format_available(src)` + `format_available(dst)` + `pair_available`); if none qualify it returns the highest-priority claimant (so `run_job`'s error message stays sensible). This mirrors `targets_for`, which prefers the available converter — otherwise the UI could offer a pair via an available low-priority converter while `resolve` routed it to an unavailable high-priority one. `MarkupConverter` (pandoc) sets `priority=10` to win the office→markup pairs it explicitly overrides (`_OFFICE_OVERRIDE_OUT` in `markup.py`, currently `{md, txt}` — docx→md/txt is now claimed at higher priority by `TextDocConverter`, so this override is also the fallback when python-docx is absent; it still covers odt→md/txt. Do **not** add `html` back there: docx/odt→html must stay on `DocumentConverter`/LibreOffice, which is the only path that preserves cell colors/shading via inline CSS; pandoc silently drops them).
- `data.py`: CSV/TSV are read as text with the **sniffed delimiter** (`;` CSVs, kept on csv→csv) and encoding (UTF-8, then cp1252/latin-1), header assigned by hand so duplicate columns survive (renamed only toward json/yaml/xml records, with a runtime lossy verdict). Same-format xlsx/ods/xml/**yaml** are byte copies; yaml→json is **lossy** (comments, YAML 1.1 booleans, dates → ISO strings).
  - `plaintext.py` (priority 15) owns txt→md in-process: Markdown symbols escaped, line breaks kept as hard breaks, indentation as `&nbsp;` — pandoc used to re-flow the text under a LOSSLESS badge.
  - `audio.py`: wav/flac targets keep the **source sample format** probed with ffprobe (`probe_audio`; 24-bit stays 24-bit, float WAV stays float). FLAC from float audio, an explicit lower `bit_depth`, or resample/channels/loudnorm options make the verdict lossy (decided at runtime once the source depth is known).
- **Detection** (`core/detection.py`): content beats the extension for binary formats and for JSON/XML that parse, but the weak text sniffs (yaml/csv/tsv) yield to a different **text** extension (`.md`, `.txt`, …) — a README with lists used to become YAML. BMP needs a valid DIB header, not just `BM`. `docmodel.types.is_bullet`: `-`/`–`/`*` need a following space (so `-5 °C` stays text) and `—` is never a bullet.
- PDF reading: a PDF is "scanned" only if it has <10 chars **and** its first pages contain images (a one-word text PDF is text); an empty result is an error, never an empty file. Paragraph indent/alignment and list levels are measured inside the paragraph's **column** (`_column_gutters`: a gutter needs ≥3 lines on each side), not from the page margin.
- **Cancel**: `run_job` returns `ConversionResult(cancelled=True)` without starting when the token is already set (queued jobs), ffmpeg is killed as before, and `TextDocConverter` checks between phases. The GUI shows `Cancelled` (re-convertible, not recorded in history).
- `gui/` — PySide6 UI; contains **zero** conversion logic.
- External tools are detected at runtime, never assumed on PATH: `deps.find_ffmpeg/find_ffprobe/find_soffice` also search standard install dirs and a bundled `bin/`.
- **Engine mode** (`core/engine.py`): session-persisted **FULL vs PORTABLE**, toggled live from the toolbar. Drives which converter pairs are offered — FULL requires LibreOffice for faithful Office conversions; PORTABLE falls back to the pure-Python paths (pdf/rtf/pandas/Pillow/ffmpeg). Same "honest availability" principle as the verdict system: a pair unavailable in the current mode shows greyed out with a reason, never silently downgrades.

## Testing

- Run: `python -m pytest -q` (config in `pyproject.toml`, `testpaths=["tests"]`).
- GUI tests set `QT_QPA_PLATFORM=offscreen` — keep that when adding GUI tests, or they need a display.
- Audio/video tests `skipif` ffmpeg/ffprobe absent; document tests `skipif` LibreOffice absent; OCR scanning is gated with a mocked chain (no OCR install needed); `test_mesh3d.py` `importorskip`s trimesh. A passing run may be skipping these — check the skip count. (Full run without the local corpus: **325 passed** on Linux, measured 2026-10-26 after the review fixes; 2 tests are Windows-specific there — `test_clean_subprocess_env_frozen_purges_bundle_from_path` uses a `C:\` path and `test_pdf_to_docx_builds_real_word_structure` expects Calibri where Linux LibreOffice embeds Carlito. With the corpus, xfails are corrupt/encrypted corpus files.)
- **Real-document corpus:** `tests/test_corpus.py` compares the reconstructed structure (reading order, headings/levels, lists, table grids, images, page breaks) against JSON baselines. Put real PDF/DOCX in `tests/corpus/local/` (gitignored; or set `CONVERTER_CORPUS_DIR`) and create baselines with `CORPUS_UPDATE=1 python -m pytest -q tests/test_corpus.py`, then review/correct the JSON. In update mode an unreadable file without a baseline is skipped; if a baseline exists, reading must still succeed or the test fails. See `tests/corpus/README.md`. This is the measurement harness for future engine changes — run it before/after touching `docmodel/`.
- To verify GUI visuals truthfully (icons, focus rings, real fonts), render on the **native** Qt platform, not offscreen (offscreen lacks window activation and font glyphs).

## Linting

- ruff (`pyproject.toml`, `[tool.ruff]`): line-length 120, target py310, `select = ["F","I","W","B","UP"]` — deliberately does **not** enable whitespace/line-length rules, to avoid fighting the codebase's hand-aligned formatting style.
- A `PostToolUse` hook (`.claude/settings.local.json`) already runs `ruff check --fix --unfixable F401` automatically after every Write/Edit on a `.py` file — no need to manually re-run ruff after editing.

## Subprocess gotcha (important)

Spawn **every external tool** (soffice, ffmpeg, ffprobe, ocrmypdf) with `deps.clean_subprocess_env()`. A PyInstaller-frozen exe injects bundle dirs into `PATH`; without cleaning, LibreOffice's own Python loads our `python313.dll` and export filters fail ("no export filter for docx"). `_libreoffice.py` and `_ffmpeg.py` already do this — don't bypass it. `_ocr.py` runs OCRmyPDF through `_libreoffice.run_with_timeout` (same env cleaning + hard timeout); OCRmyPDF locates Ghostscript via the Windows registry, so the cleaned PATH does not break it. The structured PDF reader itself is in-process (pdfminer) and has no child process.

`run_ffmpeg` also has a watchdog thread (kills ffmpeg on cancel-while-blocked or after 120 s with no `-progress` output) and `probe_duration` passes `timeout=15`; ffmpeg/pandoc/pdfminer remove their partial output on failure/cancel.

## Packaging (PyInstaller)

- Build: `pyinstaller converter.spec --noconfirm --clean` (onedir; see `/package` skill for the full build+verify flow).
- **License texts**: the spec copies `licenses/` (GPL-3/LGPL-2.1 for ffmpeg, GPL-2 for pandoc, LGPL-3 for Qt), `LICENSE` and `THIRD_PARTY_NOTICES.md` into `dist/Converter/` next to the exe, and **aborts the build** if a GPL tool is bundled without its license file.
- **Kill any running `Converter.exe` before rebuilding** — a live process locks files under `_internal`, and `--clean` fails with `PermissionError: [WinError 32]` trying to remove `dist/Converter`.
- Entry point is **`converter_app.py`** (absolute import). Do **not** point PyInstaller at `converter/__main__.py` — its relative imports have no package context when frozen, which silently drops Qt from the bundle. `python -m converter` still works via `__main__.py`.
- ffmpeg/ffprobe bundle into `_internal/bin`; assets into `_internal/assets`. Config/presets/history always live in `%APPDATA%\Converter`, never the bundle.
- **Verification tripwires** (see `/package` skill): `_internal/torch` must **NOT** exist (was accidentally bundled once at 4GB); total bundle size was ≈1.07 GB with the old pdf2docx tree (`bin/` ffmpeg+ffprobe+pandoc alone 655 MB) — multi-GB still indicates a bundling error. (`trimesh` adds only ~300 KB; the MIT pdf stack is small.)
- `trimesh` lazy-imports its exchange loaders (stl/gltf/ply/obj/threemf), so the spec collects them explicitly: `hiddenimports += collect_submodules("trimesh")` and `datas += collect_data_files("trimesh")` (its `resources/` schema+templates). Without these the exe imports trimesh but fails every 3D conversion. `python-docx` needs `datas += collect_data_files("docx")` (its `default.docx` / default-*.xml templates are opened at runtime). `lxml` (for 3mf) is **not** added explicitly — it arrives via python-docx (pikepdf is excluded).
- The shipped exe has a built-in **`--selftest <path>` CLI flag** — runs one conversion per category via `run_job` with Python stripped from PATH, writes PASS/FAIL + per-category results to a file. Use it as a real smoke test of the frozen build, not just a launch check. **It does not yet cover model3d**; the frozen 3D path is verified with `--convert <src> <dst> <out> <report>` instead (proven: stl→glb and 3mf→stl, the latter exercising the bundled threemf loader + lxml).
- The structured document engine is **in-process** (no child process, no extra CLI flag). `--selftest` exercises it in PORTABLE (`portable pdf->txt/md/docx/html`) and checks `pdf struct writer-targets` (docx/md/txt/html available) in FULL.
