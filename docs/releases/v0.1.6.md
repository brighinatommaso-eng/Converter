# v0.1.6 - A setup that behaves like a real app

Converter 0.1.6 is an installer release: the Windows setup now installs the app
the way a paid desktop app does — it shows up where you look for it, with the
right icon, and the Linux packages carry the metadata that software stores
expect. The conversion results are unchanged.

## Downloads

| File | For | How |
|------|-----|-----|
| `Converter-v0.1.6-setup.exe` | **Windows** | Run it: installs for your user only and updates an existing installation. |
| `Converter-v0.1.6-windows.zip` | Windows, portable | Extract the whole folder and run `Converter.exe`. |
| `converter_0.1.6_amd64.deb` | Ubuntu, Debian, Mint | `sudo apt install ./converter_0.1.6_amd64.deb` |
| `Converter-v0.1.6-x86_64.AppImage` | Other Linux distros | `chmod +x Converter-*.AppImage` and run it. |

## Windows: the app is where you expect it

- **Start menu and desktop.** The setup always creates the Start menu entry and
  offers the desktop shortcut as a visible choice, on by default. Previously the
  desktop shortcut was off by default and the Start menu entry was easy to miss
  (Windows 11 keeps app shortcuts under *All apps*).
- **The right icon, everywhere.** The icon file now stores its small sizes in
  the classic Windows format instead of PNG-compressed frames. Explorer, the
  shell and the taskbar read every icon file the same way now, so the
  "generic Windows icon" that used to show up until Windows was restarted is
  gone.
- **No restart needed for the icon.** After installing, the setup refreshes the
  Windows icon cache and asks the shell to redraw, so the new icon appears
  immediately.
- **One identity.** The app declares its Windows identity (AppUserModelID) and
  the installer registers that identity with its icon. The taskbar groups the
  windows under the Converter name and logo, not under a generic one.
- **A setup with manners.** The wizard shows the license, a short welcome and a
  closing page, the file properties of `setup.exe` carry the product name,
  version and publisher, and the app starts at the end if you want it to.
- **The portable zip** now ships a README that explains what each folder is and
  where your settings live.

## Linux: packages that describe themselves

- **The AppImage menu entry starts the app.** Its launcher now points at the
  AppImage's own entry point; before, the entry could point at a command that
  does not exist outside the `.deb`.
- **Metadata for the software stores.** GNOME Software, KDE Discover and Plasma
  now read Converter's name, description, license, icon and version instead of
  showing a bare entry.
- **A Debian-style changelog and file checksums** travel with the `.deb`.
- **The menu entry is translated** (English and Italian).

## The AI layout model no longer stalls the machine

The local layout model (PP-DocLayoutV2) runs on the CPU through ONNX Runtime.
The runtime was left with its defaults, which start one thread per core and let
those threads spin when they have nothing to do. On a small machine (or a busy
one) the PDF→Word conversion looked frozen: minutes of nothing, then the file
appeared. The model now uses a bounded number of threads and no spinning, so
the conversion takes the time it really takes.

## What the build now proves

Every release is checked on the machine that builds it, not just compiled:

- the installed app has a Start menu entry **and** a desktop shortcut, and the
  shortcut points at the installed executable;
- the executable really carries the Converter icon (compared pixel by pixel
  against the icon file);
- the Windows identity is registered with its icon;
- the installed copy passes its self-test;
- uninstalling removes the executable, both shortcuts and the registration;
- the AppImage contains a working menu entry, its metadata and its license.

The automated suite is green: **566 tests pass**, including the document corpus
re-measured on the real-world set. A test that hangs now fails with its name
instead of silently eating the runner's time limit.

## The document corpus, re-measured

The local corpus baselines were older than the last engine work, so the
comparison was measuring a stale snapshot. Refreshed and reviewed: the engine
now reads content controls, rich text and placeholder fields in Word files that
used to come out empty, and recovers text that used to disappear from some PDFs
(one test file went from 208 to 4,080 characters). No document lost text: on the
PDF set the number of extracted characters is the same as before or higher.
